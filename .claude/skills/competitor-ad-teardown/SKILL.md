# Competitor ad teardown

Purpose: learn **why** an ad works so we can make a better, different one. We never copy footage, scripts, music or branding. We extract patterns and look for the angles nobody has claimed.

## What to capture per ad (one row each)

| Field | What to write |
|---|---|
| url, advertiser, platform | |
| live since / variations | start date (longevity = profitability signal); number of versions the advertiser runs |
| format | UGC talking head · demo/b-roll + VO · motion graphic · slideshow · static · carousel · green-screen · street interview |
| hook (0-3s) | exact words + what's on screen in the first frame |
| hook type | problem callout · POV · negative ("stop doing X") · demo-first · curiosity gap · comparison · price anchor · social proof · ASMR/satisfying · question |
| angle | the core reason-to-buy (pain, desire, identity, fear, gift, convenience, savings) |
| structure | beat list with timestamps: hook → problem → demo → proof → offer → CTA |
| proof | demo, numbers, reviews, creator, before/after (object) |
| offer | price, discount, bundle, guarantee, shipping promise |
| production | pace (cuts/10s), captions style, music/VO, presenter type |
| comments | top objections and desires in viewers' words |
| compliance smell | unsupported claims, fake urgency, fake reviews (avoid all of these yourself) |

## Synthesis (what the teardown must output)

1. **Saturated angles**: what 3+ advertisers already say; we need a sharper version or a different angle.
2. **Unclaimed angles**: reasons-to-buy visible in comments/reviews that no ad leads with. Usually the best test.
3. **Format gaps**: e.g. everyone runs UGC, nobody runs a clean demo with motion-graphic callouts.
4. **Objections to pre-empt**: from comments (size, quality, "does it really work", shipping time).
5. **Hook bank additions**: 5-10 hooks *inspired by*, not copied from, what works.
6. **Benchmarks**: typical video length, cut pace and caption style in this niche.

Save the synthesis to the product (`notes` / `angles`) and add durable cross-product patterns to the playbook via the self-improver (don't write the playbook directly unless you are the self-improver).
